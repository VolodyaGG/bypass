# Публичная версия для ИДЗ2

Публичная версия выполняет основной учебный сценарий из PRD. Проверяющий входит
в общий тестовый профиль, запускает настоящий Molecule, получает журнал и итог.
Настройки и последний результат сохраняются в браузере. Используйте тестовые данные.

Общий профиль предназначен для демонстрации. Его задания видны всем, кто знает
тестовый пароль. Персональных серверных записей в публичной версии нет.
Локальный режим управления собственным VPS сохраняется.

## Автоматические проверки

Workflow `.github/workflows/publication.yml` запускается для PR и push в main
и ветку реализации. Он устанавливает зависимости из lock-файла, запускает pytest,
собирает Docker-образ и выполняет HTTP smoke-тест против собранного контейнера.
Smoke проверяет вход, ошибку пустого адреса, запрет реального деплоя, настоящий
Molecule с идемпотентностью и проверкой, SSE и выход.

После успешного smoke образ отправляется в GHCR с тегом полного SHA коммита.
Pull request выполняет проверки без публикации образа.

## Первый запуск на ВМ

Нужны Docker Engine и Compose plugin, домен с DNS-записью на эту ВМ
и свободные входящие TCP 80/443. Проверьте, что эти порты не заняты текущим VPN
или другим веб-сервером.

1. Создайте `/opt/bypass` с правом записи для пользователя деплоя.
2. Скопируйте туда `deploy/compose.yaml`, `deploy/Caddyfile` и
   `deploy/.env.example` как `.env`.
3. Заполните домен, тег проверенного образа, имя и тестовый пароль.
   Ограничьте права `.env` командой `chmod 600 /opt/bypass/.env`.
4. Сделайте пакет GHCR публичным или настройте на ВМ доступ для чтения пакета.
5. Выполните `docker compose --env-file .env -f compose.yaml up -d --wait`.

Caddy выпускает и продлевает TLS-сертификат. Данные профиля и сертификаты хранятся
в отдельных именованных Docker volumes. Для их сохранения используйте
`docker compose down` без флага удаления volumes.

Имя и пароль из окружения создают профиль при первом запуске пустого volume.
Изменение переменной пароля после этого не меняет существующий профиль.

## Автоматическая публикация

В GitHub Environment `production` настройте Secrets:

- `SSH_HOST`, `SSH_USER`, `SSH_KEY` для выделенного пользователя деплоя.
- `SSH_KNOWN_HOSTS` с проверенным SSH host key ВМ.
- `BYPASS_PASSWORD` с тестовым паролем для HTTP smoke.

В Repository Variables задайте `DEPLOY_ENABLED=true`.
В Environment Variables задайте `BYPASS_URL=https://ваш-домен` и
`BYPASS_PROFILE` с именем из серверного .env.

Деплой выполняется после тестов и сборки для main, а также при ручном запуске
workflow на выбранной ветке. Он загружает compose-конфигурацию, устанавливает
образ текущего SHA и проверяет публичный HTTPS основным сценарием.
При ошибке шаг помечается неуспешным. Автоматический откат не реализован.
Для отката запустите Compose с предыдущим успешным тегом образа.

## Ограничения и аудит

- В публичном режиме разрешены только health, демо, его журнал и отмена.
  API реального деплоя, клиентов, секретов и подписок закрыты на сервере.
- Образ собирается по списку разрешённых файлов. Локальные данные, .env,
  ansible/nider и пользовательские ключи исключены из build context.
- Приложение работает без root, без Docker socket и SSH-ключей.
- Переданные proxy headers доверяются только внутри закрытой сети Compose.
  Порт приложения не публикуется на хосте.
- Настройка профиля через публичный API закрыта. Cookie имеет HttpOnly,
  SameSite=Strict и Secure при HTTPS.
- Проверяется Host, ограничены попытки входа, размер HTTP-запроса, число заданий
  в памяти и одновременные демопрогоны.
- Проверка исходников не заменяет проверку всей истории Git на реальные секреты
  перед публикацией. Прежний каталог ansible/nider требует отдельной проверки
  владельцем, поскольку содержит сведения о реальном сервере.

Перед сдачей откройте HTTPS в приватном окне, войдите тестовым профилем,
пройдите демо и обновите страницу. Приложите ссылку на приложение и успешный
workflow того же коммита. Результаты CI и публичного smoke доступны в Actions.

## Render Free без собственной ВМ и домена

В корне репозитория есть `render.yaml` для бесплатного Docker Web Service.
Подключите ветку `feat/idz2-publication-ci-cd` как Blueprint.
Render выдаёт HTTPS-адрес, задаёт hostname через `RENDER_EXTERNAL_HOSTNAME`
и генерирует тестовый пароль в `VPNFORGE_DEMO_PASSWORD`.
Имя профиля — `reviewer`. Пароль смотрите в Environment сервиса и сообщите проверяющему.

Автопубликация настроена после успешных CI checks. В этом варианте Caddy и SSH
не требуются. Сервис слушает порт 8000 из Dockerfile.

Free-сервис засыпает после 15 минут без обращений. После пробуждения локальные
SQLite и сессии создаются заново с тем же именем и паролем из Environment.
Последний результат и форма остаются в localStorage браузера. Для этого демо
постоянный диск не требуется. Платный диск и платная БД не создаются.

Контейнерный smoke в Actions ограничен 512 MB RAM. Проверка на настоящем
Render дополнительно нужна для подтверждения времени выполнения на его CPU.
