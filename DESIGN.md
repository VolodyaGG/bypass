# bypass · Дизайн интерфейса

## Направление

У **bypass** одна панель для настройки VPN и просмотра результата. Режим запуска выбирается рядом с основной кнопкой. При смене режима форма сохраняет введённые значения, а журнал явно показывает, какой запуск открыт.

Шапка, форма входа и журнал используют Liquid Glass. Блоки настроек лежат на общем фоне и разделены линиями.

## Референсы и применение

Четыре референса с изображениями, первоисточниками и пояснениями собраны в [подборке](docs/design/references/README.md). В таблице перечислены решения, адаптированные для bypass.

| Референс | Что используем в bypass | Состояние |
| --- | --- | --- |
| [Linear](docs/design/references/linear-workspace.png) | Чёткие границы рабочих областей, общие оси подписей и полей, спокойные разделители | Настройки и журнал разделены; подписи и поля выровнены по общим осям, расстояние между колонками 16–28 px |
| [Railway Build Logs](docs/design/references/railway-build-logs.png) | Отдельная область журнала с заголовком запуска, текстовым статусом и моноширинным выводом | Применено в компоновке журнала; поиск и вкладки Railway в MVP не предусмотрены |
| [Apple Liquid Glass](docs/design/references/apple-liquid-glass.jpg) | Полупрозрачные поверхности, размытие фона и тонкий светлый край у элементов управления | CSS-интерпретация уже есть у шапки, входа и журнала; физическое преломление не реализовано |
| [Proton Account](docs/design/references/proton-password.png) | Явные подписи имени и пароля, вертикальный порядок полей, показ пароля и одна основная кнопка входа | Пароль скрыт по умолчанию. Кнопка «Показать» есть у основного поля и у поля подтверждения при создании профиля |

Linear, Railway и Proton дают примеры веб-интерфейсов. Apple используется только как ориентир материала: мобильную или настольную навигацию macOS в веб-панель не переносим. Разные палитры источников объединяет собственная графитово-зелёная тема bypass.

Одна главная кнопка запуска, общие оси полей и непрозрачный фон под строками журнала реализованы в CSS. Стекло используется на ограниченном числе поверхностей. При недоступном `backdrop-filter` панели имеют непрозрачную базовую заливку. Радиокнопки и флажки доступны с клавиатуры, фокус и ошибка имеют видимый контур. Уведомления используют видимое состояние Bootstrap и область `aria-live`. Логотип `b` с маршрутом и схема соединения остаются авторскими элементами bypass.

## Компоновка

| Область | Содержимое |
| --- | --- |
| Страница входа | Слева заголовок и линия маршрута, справа форма с именем и паролем. При первом запуске добавляется повтор пароля. На узком экране форма идёт под заголовком |
| Шапка | Авторский знак в форме строчной `b` с ответвлением маршрута, название `bypass`, помощь, имя профиля и кнопка «Выйти». Тот же знак используется во вкладке и в схеме на входе |
| Настройки | Адрес сервера, SSH, протоколы. DNS, TLS, маршрутизация и параметры OpenFlux раскрываются по необходимости |
| Запуск | Переключатель «Демо / На VPS», описание режима и одна главная кнопка. На узком экране описание переносится под переключатель и кнопку. Линия рядом с заголовком показывает выбранную цель, localhost или VPS по SSH |
| Журнал | Название режима, текущий этап, вывод Ansible или Molecule и итог. На широком экране находится справа от формы, на узком идёт после настроек |
| Клиенты | Список клиентов и действия «Копировать подписку» и «Скачать Xray JSON» для реального сервера |

В секции DNS и сертификатов три источника: «выпустить автоматически» (по умолчанию),
«с этого компьютера» и «уже на VPS». Автоматический режим показывает краткое описание
выпуска и продления Let's Encrypt и требования к домену и порту 80; поля загрузки файлов
и путей на сервере скрыты. Для других источников отображаются только соответствующие
поля. Демо явно не выполняет реальный выпуск сертификата.

Домен вводится одним полем «Полный домен» с примером `vpn.example.com`. Подсказка
объясняет, что нужен поддомен, направленный на VPS, без протокола и порта. Отдельных
полей Root и Sub в форме нет; старые сохранённые значения автоматически объединяются.

## Компоненты

Библиотека компонентов — **Bootstrap 4.5.0**. Её CSS хранится в `vpnforge/web/static/vendor/bootstrap.min.css` и подключён на странице входа и в панели перед собственными стилями bypass.

| Компонент Bootstrap | Применение в bypass |
| --- | --- |
| `form-control` | Поля имени и пароля на входе, адрес VPS в панели |
| `btn`, `btn-primary`, `btn-outline-light` | Вход, запуск, помощь, выход и действия с журналом |
| `card`, `card-body` | Форма входа и контейнер журнала |
| `alert`, `alert-danger` | Ошибки входа и проверки формы |

Поверх компонентов настроен стиль Liquid Glass в `workspace.css`. Свёрнутые разделы используют HTML-элемент `details`, журнал и поток событий реализованы в приложении. Контурные иконки взяты из Tabler Icons 3.46.0 и включены локально вместе с MIT-лицензией.

## Состояния запуска

| Состояние | Что видит пользователь |
| --- | --- |
| Ожидание | Поля формы доступны. Журнал показывает подсказку «Логи появятся после запуска» |
| Ошибка формы | Проблемное поле выделено, рядом написано, что исправить. Фокус переходит к первому проблемному полю |
| Идёт запуск | Видны режим, текущий этап и новые строки журнала. Повторное нажатие на запуск заблокировано |
| Восстановление связи | Журнал показывает «Восстанавливаем связь с журналом», настройки и повторный запуск заблокированы. После переподключения появляются только ещё не полученные события |
| Журнал больше недоступен | Показано «Статус запуска неизвестен» с пояснением о возможном перезапуске сервера. Интерфейс не объявляет задачу неудачной без результата сервера |
| Успех | Для демо отображается «Симуляция завершена». Для реального запуска отображается «Сервер настроен» и становятся доступны действия с клиентами |
| Ошибка запуска | Видны причина и журнал. Введённые поля сохраняются для повторной попытки |
| Отмена демо | Журнал остаётся на экране со статусом «Запуск отменён» |
